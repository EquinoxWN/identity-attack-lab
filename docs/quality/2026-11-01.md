# Quality check against the 10 rules (2026-11-01)

Checked on 2026-11-09 on Windows 11 with Python 3.14.5 (pytest 9.2.0, ruff 0.17.4, mypy 2.4.1
strict, pip-audit 2.10.1). The Python code reads `lab/lab.toml` and BloodHound JSON, writes
generated files, and makes no network calls. The generated PowerShell runs only inside the lab VMs.

## Rules

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | No network or service calls in Python. Every parse error is re-raised with the file name (`SpecError`, `CollectionError`); `grep -rn except src` finds 9 handlers, each re-raises with context, turns the error into a reported violation, or cleans up a temp file and re-raises. The CLI maps input errors to exit 2. Generated PowerShell uses `$ErrorActionPreference = 'Stop'`, checks `dsacls` exit codes, and its waits for AD and DNS are bounded (10 minutes). CI downloads use `curl --retry 3 --max-time`, job `timeout-minutes`. |
| 2 | Writes safe to retry | pass | `atomic_write` writes a temp file in the same folder, fsyncs, renames, and skips unchanged files (`test_write_all_is_idempotent_and_drift_detects_edits`, `test_atomic_write_leaves_no_temp_file_on_failure`). Every provisioning script checks before it changes (already a DC, already joined, member present, SPN present, `-Force` task registration). |
| 3 | No race conditions | pass | Single-process CLI, no threads; nodes and edges live in one in-memory graph per call. Vagrant brings the DC up before the member (DC defined first, `test_vagrantfile_brings_the_dc_up_first`). |
| 4 | Don't trust the clock | pass | No stored timestamps (generated files are deterministic). The only durations, the provisioning waits, use `[Diagnostics.Stopwatch]` (monotonic). The lab VMs are set to UTC in both answer files. |
| 5 | Read before changing | pass | No environment variables are read (`grep -rnE "environ|getenv" src`: none). Packer variables are documented in the template; `PACKER_PLUGIN_PATH`/`PACKER_CONFIG_DIR` used by `make packer-validate` are documented in the README. SharpHound field names were checked against the model round trip. |
| 6 | Never break compatibility | pass | New repository; the CLI exit-code contract (0/1/2) is documented in `cli.py` and tested. Generated-file drift is ignored for CRLF only, so a Windows checkout does not break `render --check`. |
| 7 | One source of truth | pass | `lab/lab.toml` generates the Vagrantfile, scripts and model; `render --check` fails on drift. The box password is shared by `render.py`, the Packer template and both answer files and a test asserts they agree. Version 0.1.0 in `pyproject.toml` and `__init__.py` (tested). |
| 8 | Small changes, no secrets, validate input | pass | Every password must contain `EXAMPLE-NOT-A-SECRET` (spec validator, `isolation` scans scripts and answer files). Spec: unknown keys rejected, types, ranges and patterns checked, file size capped at 1 MB, lists at 500. Collections: file 100 MB, total 500 MB, 200 zip entries, compression ratio 200, read in memory without extraction (no path traversal). Values embedded in Ruby/PowerShell cannot contain quotes, backticks, `$` or newlines. No runtime dependencies. |
| 9 | Tests that can actually fail | pass | 138 tests, no skips or xfails; empty, invalid and failure paths covered (empty spec, empty collection, malformed JSON, rename failure). 18 hand mutations below, all killed. |
| 10 | Re-verify | pass | `bash .tmp/check.sh` twice: `ruff`: All checks passed; `mypy`: no issues in 16 files; `pytest`: 138 passed; `render check: 9/9`; `isolation: 10 checks run, 0 violations`; `verify: 3/3 expected paths found, 0 unexpected paths`; `packer validate`: valid; PowerShell parse: 5 scripts, 0 errors; `pip-audit`: No known vulnerabilities found; `CHECK PASS`. `audit_repo.py identity-attack-lab`: OK. |

## Defects fixed during the pass

| Where | Defect | Fix and test |
|---|---|---|
| `bloodhound._list_of` | `"Aces": {}` (an object instead of a list) was treated as "no ACEs" because `{} or []` is `[]`, so a malformed collection could lose edges silently. | Only a missing/`null` value means empty; anything else must be a list of objects. Malformed-file case `list of obj`. |
| `spec._password`, `spec._users` (security review, 2026-11-10) | Passwords and descriptions were only checked against a denylist (single and double quote, backtick, `$`, CR and LF). PowerShell also treats the Unicode quotes U+2018 to U+201B as single quotes, so such a value could close its string in the generated provisioning scripts. | Both must fully match printable ASCII (fullmatch on `[\x20-\x7E]+`), denylist kept; names, groups, hosts, SPNs and the domain already use ASCII-only patterns (the SID pattern now uses `[0-9]`, not `\d`). Defence in depth: `render_all` refuses any generated Vagrantfile or script with a character outside printable ASCII. Tests `unicode-quote-password`, `unicode-quote-description`, `test_renderer_refuses_non_ascii_even_if_validation_is_bypassed`; each fails with its check removed (M16-M18). |
| `tests/test_spec.py` | No case with exactly three character classes, so weakening the complexity rule to 3 survived (M8). | Added `no-digit-password`. |

## Known limitations

- The analyzer follows 12 control edge kinds; ADCS, GPO, delegation and trust edges are not
  modelled, so BloodHound CE can show paths `paths` does not.
- A full Packer build, `vagrant up`, a live BloodHound CE ingest and `verify` on a real collection
  have not been run (see `docs/results/m1.md`).
